# 履历式记忆

[English](README.md)

`@onenightcarnival/dsh-memory` 在左侧栏提供「记忆」入口。简历包含个人信息与能力、工作经历、项目经历；关联的经历档案记录背景、行动、观察结果、证据、经验与适用边界。

## 使用

- 「简历」以自适应宽度展示个人信息与能力、工作经历、项目经历，内容按需纵向滚动。
- 「目录」提供全局个人信息入口，工作经历、项目、档案分列浏览。选中任意工作、项目或档案，右侧显示并可编辑该条目自身内容；下一级列表独立展示。切换上级会清除下级选择。窄屏收起上游列，通过路径导航返回。未关联工作的项目显示在「独立项目」。旧版直接关联工作的档案保留在原位置。
- 同级条目按填写的经历日期排序，默认最新在前，可切换最早在前。工作和项目使用开始日期，仅知道结束日期时使用结束日期；档案使用发生日期。无日期条目在两个方向均排最后，同日保持录入顺序。创建时间仅作为元数据保留。
- 从工作经历新增项目、从项目新增档案时自动填写关联。首次安装为空白履历。
- 「允许Agent使用」是全部记忆工具的统一权限开关。开启后，Agent 可读取和修改所有条目，包括人工编辑、导入和恢复的内容，不设置逐字段权限。默认开启，控制记忆工具及配套提示的注入。开关持久化，不创建履历版本；关闭后已分派的工具调用也会被拒绝。
- 「版本历史」展示修改者、来源与字段差异。恢复版本会替换整份履历，生成新版本。
- 导出当前简历和档案的结构化 JSON，不包含版本历史或工具开关。导入与版本恢复均保留当前工具开关。导入替换当前内容、生成新版本。
- 移除条目保留历史。移除父条目前须先移除或更改引用。「清空记忆」经确认后删除全部履历、档案和版本历史，无法恢复；工具开关不变。履历版本归零，首次保存从版本 1 开始；内部并发计数保持递增，清空前的编辑草稿无法覆盖清空结果。

## 履历字段

工作经历包含公司（`organization`）、开始／结束日期（`startDate`、`endDate`）、岗位（`jobTitle`）、主要事迹（`highlights`）。每条经历记录该时间段内的一个岗位，兼任角色写入主要事迹；岗位变化时拆分经历。项目包含名称、开始／结束日期、承担角色、主要事迹和可选的工作关联；项目目标、主要工作、项目成果统一记录于主要事迹。档案包含发生日期（`date`）。

开始日期和截至日期选择器在同一行，以完整日历日期 `YYYY-MM-DD` 保存。勾选「至今」后禁用截至日期，`endDate` 保存为 `present`，经历展示为持续至今；取消勾选后截至日期留空。未知日期留空，不推断为仍在进行。具体截至日期不能早于开始日期，不自动检查经历之间的时间重叠。持续至今的条目仍按填写的开始日期排序，缺少开始日期时作为无日期条目。

## Agent 契约

| 工具 | 契约 |
|---|---|
| `memory_resume` | 返回全局个人信息、分别分页的工作与项目摘要，不包含档案正文。分页参数为 `workOffset`、`projectOffset`、`limit`。 |
| `memory_search` | 关键词检索，可按 `kind` 或工作／项目的 `scopeId` 限定范围。不区分大小写，空格分隔的关键词须全部匹配。返回 ID 和摘要，范围包含后代条目。 |
| `memory_get` | 传入 `id` 返回节点完整内容、上级路径和分页的下级摘要；`profile` 表示全局个人信息。 |
| `memory_save` | 提交最新 `stateToken`、事实性 `summary` 和按类型定义的增量 `changes`。整批成功或失败，内容变化时生成一个版本。 |

读取返回界面版本 `version` 和用于并发校验的不透明标识 `stateToken`。发现类结果默认每页 10 条，允许 1–20 条。摘要字段最多 400 字符，截断项列于 `truncatedFields`；检索片段最多 240 字符。完整字段通过 `memory_get` 读取。结果使用上述经历日期顺序。检索采用关键词匹配，不进行语义相似度检索。

每项写入包含 `kind`（`profile`、`work`、`project`、`episode`）及该类型的 `fields`。省略字段保持原值，空字符串清空字段。已有 `id` 用于更新，省略 ID 时由服务端创建并分配 ID；个人信息始终更新全局条目。新条目可声明批次内 `ref`，在 `workId` 或 `parentId` 中使用 `@ref` 关联同批条目，支持前向引用。返回值包含解析后的 `refs` 与条目 ID。新增工作须填写公司，新增档案须关联项目并提供证据引用。

`{ "kind": "remove", "id": "existing-id" }` 移除条目并保留历史；引用须提前或在同批次内移除、改绑。无内容变化不生成版本。错误包含 `code`、`message`、可选 `detail` 和 `retryable`。并发冲突后须重新读取相关条目再组织修改。Agent 工具不提供清空、导入、恢复版本或修改权限功能。

提示引导 Agent 读取相关经历，并在验证过的阶段结果产生后更新。更新依赖 Agent 在当前任务内调用工具；本版不运行后台抽取、自动会话扫描或单独的抽取模型调用。证据引用会被保存，其真实性不会自动核实。记忆作为数据提供，不覆盖当前指令。不保存凭证或完整对话流水。

## 存储与配置

数据位于 `$DSH_HOME/memory/career.json`，默认 `~/.dsh/memory/career.json`。本地会话共享一份个人履历，项目作为明确的独立条目保留。文件包含当前状态、工具开关与历史快照。历史快照仅包含履历内容。界面版本按当前历史顺序从 1 编号；API 的 `revision` 用于并发校验，`restore` 使用历史记录的内部 `revision`，不使用界面编号。写入使用独占 `.lock` 文件和原子替换。旧版本写入被拒绝；即使修改不同字段，旧版本也需要刷新。进程崩溃可能留下锁：停止全部记忆写入进程，确认锁已失效后，仅移除 `career.json.lock` 再重试。损坏数据不会被自动重置。

存储与导出格式为版本 4，支持读取和导入版本 1–3。旧工作经历的名称、角色、职责和成绩按原顺序合并至主要事迹；岗位留空，关联 ID 保持不变。旧项目目标、主要工作和项目成果按原顺序合并为主要事迹。旧时间中的完整日期、完整 ISO 日期区间转换为日期字段；不完整或有歧义的文本保存在只读 `legacyPeriod` 元数据中，明确编辑日期后移除，不推断具体哪一天。历史快照同步转换，读取不写盘，下次保存时持久化新格式。旧 `protected` 数组仅作为存储元数据保留，不限制编辑；新人工修改、导入和恢复不增加字段权限。旧条目的创建时间取首次出现的历史快照时间；缺少历史依据时显示时间未知。无创建时间的导入条目使用已有同 ID 时间或导入时间。旧版开关变更产生的历史版本保留，新开关操作不再创建版本。

容量限制：1,000 个条目、每字段 12,000 字符（主要事迹 50,000 字符）、每次 100 项变更、HTTP／导入输入 2 MiB、历史存储 32 MiB。超限拒绝修改，不自动裁剪历史。API 仅接受回环请求，要求宿主浏览器会话认证。

独立插件 ID 为 `memory`，配置 `{ enabled: false }` 关闭宿主功能。toolkit 模块键为 `memory`，设为 `false` 同时关闭宿主与界面。独立安装和集成安装互斥。

## 开发

Node.js 22.19+ 或 24+，pnpm 11；dsh `0.2.0-rc.2`。

```sh
pnpm --filter @onenightcarnival/dsh-memory build
pnpm --filter @onenightcarnival/dsh-memory typecheck
pnpm --filter @onenightcarnival/dsh-memory test
```

`src/model.ts` 定义字段与关联；`src/store.ts` 负责校验、历史和并发；宿主 API 与工具共用存储。界面字典键集一致，跟随宿主语言。测试覆盖持久化、统一权限、旧版本写入、原子失败、无效数据与版本恢复。
