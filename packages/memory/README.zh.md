# 履历式记忆

[English](README.md)

`@onenightcarnival/dsh-memory` 在左侧栏提供「记忆」入口，保存 Agent 自己的职业履历。简历包含个人信息与能力、工作经历、项目经历；关联的经历档案记录背景、行动、观察结果、证据、经验与适用边界。

## 记录类型

| 类型 | 含义 |
|---|---|
| `profile` | 唯一的全局个人信息：这个 Agent 是谁、能做什么 |
| `work` 工作经历 | 一个岗位：在一份岗位描述下，为一个组织或委托方连续担任的一个角色；角色或委托方变化即为新的工作经历 |
| `project` 项目经历 | 岗位内的一项交付或一段工作；无所属工作的为独立项目 |
| `episode` 档案 | 项目中的一段具体经历：发生了什么、观察到什么、得到什么教训，并附证据 |

界面中 `episode` 显示为「档案」。同一说明同时写入工具 schema 与系统提示。

## 使用

- 「简历」以自适应宽度展示个人信息与能力、工作经历、项目经历，内容按需纵向滚动。
- 「目录」提供全局个人信息入口，工作经历、项目、档案分列浏览。选中任意工作、项目或档案，右侧显示并可编辑该条目自身内容；下一级列表独立展示。切换上级会清除下级选择。窄屏收起上游列，通过路径导航返回。未关联工作的项目显示在「独立项目」。旧版直接关联工作的档案保留在原位置。
- 同级条目按填写的经历日期排序，默认最新在前，可切换最早在前。工作和项目使用开始日期，仅知道结束日期时使用结束日期；档案使用发生日期。无日期条目在两个方向均排最后，同日保持录入顺序。创建时间仅作为元数据保留。
- 从工作经历新增项目、从项目新增档案时自动填写关联。首次安装为空白履历。
- 「允许Agent使用」是全部记忆工具的统一权限开关。开启后，Agent 可读取和修改所有条目，包括人工编辑、导入和恢复的内容，不设置逐字段权限。默认开启，控制记忆工具及配套提示的注入。开关持久化，不创建履历版本；关闭后已分派的工具调用也会被拒绝。
- 「版本历史」展示修改者、来源与字段差异；选中版本时按需读取该版本与前一版本的内容。恢复版本会替换整份履历，生成新版本。
- 导出当前简历和档案的结构化 JSON，不包含版本历史或工具开关。导入与版本恢复均保留当前工具开关。导入替换当前内容、生成新版本。
- 移除条目保留历史。移除父条目前须先移除或更改引用。「清空记忆」经确认后删除全部履历、档案和版本历史并回收文件空间，无法恢复；工具开关不变。履历版本归零，首次保存从版本 1 开始；内部并发计数保持递增，清空前打开的编辑草稿被拒绝。

## 履历字段

工作经历包含公司（`organization`）、开始／结束日期（`startDate`、`endDate`）、岗位（`jobTitle`）、主要事迹（`highlights`）。每条经历记录该时间段内的一个岗位，兼任角色写入主要事迹；岗位变化时拆分经历。项目包含名称、开始／结束日期、承担角色、主要事迹和可选的工作关联；项目目标、主要工作、项目成果统一记录于主要事迹。档案包含发生日期（`date`）。

开始日期和截至日期选择器在同一行，以完整日历日期 `YYYY-MM-DD` 保存。勾选「至今」后禁用截至日期，`endDate` 保存为 `present`，经历展示为持续至今；取消勾选后截至日期留空。未知日期留空，不推断为仍在进行。具体截至日期不能早于开始日期，不自动检查经历之间的时间重叠。持续至今的条目仍按填写的开始日期排序，缺少开始日期时作为无日期条目。

## Agent 契约

| 工具 | 契约 |
|---|---|
| `memory_get` | 读取一个节点：完整内容、上级路径和分页的下级摘要。省略 `id` 从根节点（全局个人信息）开始，其下级为工作经历和独立项目；工作的下级为项目，项目的下级为档案。 |
| `memory_save` | 提交最新 `stateToken`、事实性 `summary` 和按类型定义的增量 `changes`。整批成功或失败，内容变化时生成一个版本。 |

读取返回界面版本 `version` 和用于并发校验的不透明标识 `stateToken`。下级摘要默认每页 10 条，允许 1–20 条，按上述经历日期排序；摘要字段最多 400 字符，截断项列于 `truncatedFields`，`childCount` 给出再下一级的数量。完整字段通过该节点自身的 `memory_get` 读取。不提供关键词或语义检索，Agent 沿树逐层展开相关分支。

每项写入包含 `kind`（`profile`、`work`、`project`、`episode`）及该类型的 `fields`；每种类型的 schema 附带上表的含义说明。省略字段保持原值，空字符串清空字段。已有 `id` 用于更新，省略 ID 时由服务端创建并分配 ID；个人信息始终更新全局条目。新条目可声明批次内 `ref`，在 `workId` 或 `parentId` 中使用 `@ref` 关联同批条目，支持前向引用。返回值包含解析后的 `refs` 与条目 ID。新增工作须填写公司，新增档案须关联项目并提供证据引用。

`{ "kind": "remove", "id": "existing-id" }` 移除条目并保留历史；引用须提前或在同批次内移除、改绑。无内容变化不生成版本。错误包含 `code`、`message`、可选 `detail` 和 `retryable`。并发冲突后须重新读取相关条目再组织修改。Agent 工具不提供清空、导入、恢复版本或修改权限功能。

提示引导 Agent 读取相关经历，并在验证过的阶段结果产生后更新。更新依赖 Agent 在当前任务内调用工具；不运行后台抽取、自动会话扫描或单独的抽取模型调用。证据引用会被保存，其真实性不会自动核实。记忆作为数据提供，不覆盖当前指令。不保存凭证或完整对话流水。

## 存储与配置

数据位于 `$DSH_HOME/memory/career.sqlite`，默认 `~/.dsh/memory/career.sqlite`，使用 Node 内置的 `node:sqlite`，无原生扩展。本地会话共享一份个人履历，项目作为明确的独立条目保留。

| 表 | 内容 |
|---|---|
| `meta` | 格式版本、并发计数 `revision`、工具开关 |
| `blobs` | 按内容哈希去重的条目 JSON |
| `entries` | 当前履历按显示顺序引用的条目 |
| `revisions` | 版本的时间、修改者、来源与摘要 |
| `revision_entries` | 每个版本按显示顺序引用的条目 |

未变化的条目在版本间共享同一份内容；读取当前履历不加载历史内容。界面版本按当前历史顺序从 1 编号；API 的 `revision` 用于并发校验，`restore` 使用历史记录的内部 `revision`，不使用界面编号。所有写入在一个独占事务内完成，旧版本写入被拒绝；即使修改不同字段，旧版本也需要刷新。另一进程正在写入时等待至多 5 秒，超时返回可重试的 `busy`。删除的内容即时覆写，清空后回收文件空间。损坏数据不会被自动重置。数据目录不要放在 iCloud、Dropbox 等同步盘内。

HTTP 接口：`GET` 返回当前状态与版本元数据；`GET ?diff=<revision>` 返回该版本与前一版本的条目，首个版本与空履历比较；`POST` 提交修改；`PATCH` 切换工具开关；`DELETE` 清空。接口仅接受回环请求，要求宿主浏览器会话认证。

### 旧文件迁移

数据库为空且同目录存在 `career.json` 时，首次打开读取并导入全部内容与版本历史，然后将其改名为 `career.json.migrated`。数据库已有内容时不读取同目录的 JSON 文件。旧 JSON 解析失败时打开失败，不自动重置；修正或移走该文件后重试。

导出格式为版本 4，支持导入版本 1–3。旧工作经历的名称、角色、职责和成绩按原顺序合并至主要事迹；岗位留空，关联 ID 保持不变。旧项目目标、主要工作和项目成果按原顺序合并为主要事迹。旧时间中的完整日期、完整 ISO 日期区间转换为日期字段；不完整或有歧义的文本保存在只读 `legacyPeriod` 元数据中，明确编辑日期后移除，不推断具体哪一天。历史快照同步转换。旧 `protected` 数组仅作为存储元数据保留，不限制编辑；新人工修改、导入和恢复不增加字段权限。旧条目的创建时间取首次出现的历史快照时间；缺少历史依据时显示时间未知。无创建时间的导入条目使用已有同 ID 时间或导入时间。旧版开关变更产生的历史版本保留，新开关操作不再创建版本。

### 限制与配置

容量限制：1,000 个条目、每字段 12,000 字符（主要事迹 50,000 字符）、每次 100 项变更、HTTP／导入输入 2 MiB。超限拒绝修改。

独立插件 ID 为 `memory`，配置 `{ enabled: false }` 关闭宿主功能。toolkit 模块键为 `memory`，设为 `false` 同时关闭宿主与界面。独立安装和集成安装互斥。

## 开发

Node.js 22.19+ 或 24+，pnpm 11；dsh `0.2.0-rc.2`。

```sh
pnpm --filter @onenightcarnival/dsh-memory build
pnpm --filter @onenightcarnival/dsh-memory typecheck
pnpm --filter @onenightcarnival/dsh-memory test
```

| 文件 | 职责 |
|---|---|
| `src/model.ts` | 字段、关联、类型含义与排序 |
| `src/validate.ts` | 快照校验与版本 1–3 转换 |
| `src/legacy.ts` | 读取旧 `career.json` |
| `src/store.ts` | SQLite 存储、历史、事务与并发 |
| `src/tools.ts` / `src/registration.ts` | Agent 工具与系统提示 |
| `src/index.ts` / `src/http.ts` | 宿主 HTTP 接口 |
| `src/client/` | 侧栏界面 |

宿主 API 与工具共用存储。界面字典键集一致，跟随宿主语言。测试覆盖持久化、统一权限、旧版本写入、并发忙锁、原子失败、无效数据、旧文件迁移、版本差异与版本恢复。
